# 7장. 카메라, 원근 투영, 동차좌표 w

> _원근법의 핵심은 멀수록 작아진다는 문장이 아니라, clip 좌표를 w로 나누는 과정이다._

> **이번 장의 눈에 보이는 결과**  카메라 앞의 wireframe 큐브가 거리에 따라 작아지고, near/far 위치가 테스트로 정확히 0과 1의 NDC 깊이에 매핑된다.

## 왜 필요한가

3D 점을 단순히 x/z, y/z로 나누면 그림은 나올 수 있지만, 이동/회전과 합성되는 행렬 구조, near/far 깊이, clip plane을 잃는다. 동차좌표와 projection matrix를 사용하면 이 모든 규칙이 하나의 일관된 파이프라인에 들어간다.

이 과정은 왼손 view 공간에서 카메라가 +Z를 본다고 정한다. NDC x/y는 -1..1, 깊이 z는 0..1이다. OpenGL식 오른손/-Z 또는 -1..1 깊이와 섞지 않는 것이 중요하다.

## 배경지식

- <strong>View matrix</strong>는 카메라의 world transform의 역변환이다. 카메라를 오른쪽으로 옮기는 것은 world를 왼쪽으로 옮기는 것과 같다.
- <strong>Look-at basis</strong>는 `forward=normalize(target-eye)`, `right=normalize(cross(world_up,forward))`, `up=cross(forward,right)` 순서로 만든다. 통상적인 cross 식을 유지한 채 이 인자 순서로 왼손 기저를 얻는다. forward와 world_up이 거의 평행하면 cross가 0에 가까워지므로 대체 up을 선택해야 한다.
- <strong>fov_y</strong>는 세로 시야각이다. focal scale q = 1/tan(fov_y/2)이며 aspect = width/height가 x scale에 들어간다.
- <strong>w_clip = z_view</strong>로 두면 카메라 앞의 점은 양의 w를 가진다. perspective divide 뒤 x와 y가 거리에 따라 작아진다.
- **near는 0이 될 수 없다.** near를 지나치게 작게 잡으면 먼 거리에서 깊이 차이를 구별하기 어려워질 수 있다. far가 고정일 때 near가 0에 접근하면 깊이 계수 A는 1, B는 0에 접근한다. 계수가 커지는 f-near가 0에 가까운 경우와 구분한다.

## 핵심 식과 불변조건

```text
q = 1 / tan(fov_y / 2),  aspect = width / height
F = normalize(target-eye), R = normalize(cross(world_up,F)), U = cross(F,R)
V rows: [R.x,R.y,R.z,-dot(R,eye)], [U.x,U.y,U.z,-dot(U,eye)], [F.x,F.y,F.z,-dot(F,eye)], [0,0,0,1]
P rows (column vector): [q/aspect,0,0,0], [0,q,0,0], [0,0,f/(f-n),-fn/(f-n)], [0,0,1,0]
x_ndc = x_clip / w_clip,  y_ndc = y_clip / w_clip,  z_ndc = z_clip / w_clip
x_screen = (x_ndc * 0.5 + 0.5) * width
y_screen = (0.5 - y_ndc * 0.5) * height
```

## 원근 투영 행렬을 만드는 이유

깊이 z에서 세로 시야의 반폭은 직각삼각형의 정의로 `z*tan(fov_y/2)`다. 그 반폭이 NDC의 1이 되어야 하므로 위치 y를 반폭으로 나눈다.

```text
y_ndc = y / (z*tan(fov_y/2)) = q*y/z
q = 1/tan(fov_y/2)
x_ndc = q*x/(aspect*z)
```

가로 반폭은 세로 반폭의 aspect배다. 이 나눗셈을 동차좌표의 마지막 divide에 맡기면 `x_clip=q*x/aspect`, `y_clip=q*y`, `w_clip=z`가 된다.

깊이는 near n을 0, far f를 1에 보내야 한다. 행렬로 만들 수 있도록 `z_clip=A*z+B`라 놓는다. divide 뒤에는 `z_ndc=A+B/z`다.

```text
near 조건: A+B/n=0  → B=-A*n
far 조건:  A+B/f=1  → A-A*n/f=1
A*(f-n)/f=1        → A=f/(f-n)
B=-f*n/(f-n)
```

그래서 앞의 P 행렬 세 번째 행이 나온다. 유효한 입력은 유한한 `0<fov_y<π`, `aspect>0`, `0<n<f`다. n=1,f=10이면 z=1의 깊이는 0, z=2는 5/9, z=10은 1이다. view에서 중간인 z=5.5는 깊이 10/11이지 0.5가 아니다. 원근 깊이는 거리에 선형이 아니다.

### look-at의 마지막 열이 음수 내적인 이유

world 점에서 eye를 빼면 카메라 기준의 상대 위치다. 그 위치를 오른쪽 단위벡터 R에 투영하면 view x가 된다.

```text
view_x = dot(R,world-eye)
       = dot(R,world)-dot(R,eye)
```

따라서 view 행렬 첫 행은 `[Rx,Ry,Rz,-dot(R,eye)]`다. U와 F에도 같은 전개를 적용하면 나머지 행이 나온다. eye=(0,0,-3), target=(0,0,0)이면 F=(0,0,1), R=(1,0,0), U=(0,1,0)이고 world 원점의 view z는 3이다.

화면의 중간과 표면의 중간도 일반적으로 다르다. 이 나눗셈이 속성 보간에 미치는 효과를 14장에서 수치로 다시 계산한다.

## 알고리즘과 구현 순서

1. 카메라 position, target 또는 yaw/pitch, world_up으로 `F`, `R`, `U` 순서의 정규직교 basis를 만든다.
1. basis와 position으로 world-to-view 행렬을 구성한다. 별도 테스트에서 카메라 position이 view 원점으로 가는지 확인한다.
1. fov_y, aspect, near n, far f로 왼손 0..1 depth projection을 만든다. n&gt;0, f&gt;n, aspect&gt;0을 검사한다.
1. clip 이후에만 x/w, y/w, z/w를 계산한다. 정상 near clipping을 통과한 점은 w=z_view≥near>0이다. 작은 w 자체를 임의 epsilon으로 제거하지 않는다. w=0, 비유한 w 또는 비유한 나눗셈 결과를 명시적으로 거부한다.
1. NDC를 viewport로 옮길 때 y를 뒤집는다. screen 좌표는 픽셀 중심이 아니라 픽셀 셀 경계 기준의 실수 좌표다.

```text
perspective_lh_zo(fov_y, aspect, n, f):
  require 0 < n < f
  q = 1 / tan(fov_y / 2)
  return Mat4(
    q/aspect, 0, 0, 0,
    0, q, 0, 0,
    0, 0, f/(f-n), -f*n/(f-n),
    0, 0, 1, 0
  )

look_at_lh(eye, target, world_up):
  F = normalize(target - eye)
  R = normalize(cross(world_up, F))
  U = cross(F, R)
  return Mat4_rows(R.x,R.y,R.z,-dot(R,eye),
                   U.x,U.y,U.z,-dot(U,eye),
                   F.x,F.y,F.z,-dot(F,eye),
                   0,0,0,1)

viewport(ndc):
  return ((ndc.x*0.5+0.5)*W,
          (0.5-ndc.y*0.5)*H,
          ndc.z)
```

## JS-Wasm 경계

JS는 Canvas resize 때 aspect가 바뀌었다는 사실과 새 내부 width/height를 전달한다. Rust는 fov, near, far 정책과 projection 계산을 소유한다. UI에서 fov를 조절하더라도 degree를 radian으로 바꾸고 유효 범위를 검사하는 곳은 core 또는 adapter 한 곳으로 고정한다.

## 코딩 에이전트 작업 명세

- look_at_lh와 perspective_lh_zo처럼 규약이 이름에 드러나는 생성 함수를 만든다.
- near/far mapping, 화면 네 모서리, aspect 변화에 대한 수치 테스트를 먼저 작성한다.
- wireframe cube를 screen 좌표로 투영하되 아직 면 채우기나 depth는 하지 않는다.
- 개발 overlay에 fov, near, far, aspect, 선택 정점의 w와 NDC를 표시한다.

## 검증 기준

- view z=+near인 중심점은 z_ndc≈0, z=+far인 중심점은 z_ndc≈1이어야 한다.
- view z=+2의 같은 x는 z=+1일 때보다 화면 중심에 더 가깝게 나타나야 한다.
- x_ndc=-1과 1은 화면 x=0과 width에, y_ndc=1과 -1은 y=0과 height에 매핑되어야 한다.
- 카메라 position을 view 행렬에 넣으면 원점이 되고, `eye+k*forward`는 `k>0`일 때 view `(0,0,+k)`가 되어야 한다. `eye=(0,0,0)`, `target=(0,0,1)`, `world_up=(0,1,0)`이면 view가 identity여야 한다.

### 자주 생기는 오류

- OpenGL 깊이 -1..1 projection 식을 0..1 clip plane과 섞으면 near clipping과 depth가 틀어진다.
- viewport에서 width-1을 곱하고 다른 곳에서는 width 경계를 쓰면 모서리 규칙이 불일치한다. 셀 경계 0..width 규약을 고정한다.
- w가 음수인 카메라 뒤 정점을 바로 나누면 화면을 뒤집어 덮는 거대한 삼각형이 생긴다. 10장의 clipping이 먼저다.
