# 13장. 깊이 버퍼와 가려짐

> _삼각형 제출 순서가 아니라 카메라에서의 깊이가 보이는 표면을 결정하게 만든다._

> **이번 장의 눈에 보이는 결과**  서로 겹치는 삼각형을 어떤 순서로 그려도 같은 색 이미지가 나오고, 깊이 grayscale과 range heatmap debug view가 보인다.

## 왜 필요한가

색 버퍼만 쓰면 나중에 그린 삼각형이 항상 앞에 보이는 painter's algorithm이 된다. 3D mesh의 삼각형 순서는 시점이 바뀔 때마다 정렬되지 않으므로 픽셀별 깊이 비교가 필요하다.

이 과정의 NDC 깊이는 near=0, far=1이며 작은 값이 가깝다. 왼손 view의 양의 `z_view`가 멀수록 커져도 projection 뒤의 이 비교 방향은 바뀌지 않는다. 각 픽셀의 가장 작은 깊이를 저장하면 서로 다른 깊이의 opaque 표면은 제출 순서와 무관한 최종 색을 얻는다. 깊이가 정확히 같고 색이 다르면 strict < 때문에 먼저 그린 표면이 남는다.

## 배경지식

- <strong>depth buffer</strong>는 픽셀당 f32 하나이며 색 버퍼와 동일한 pixel_index를 사용한다.
- <strong>clear value</strong>는 +infinity로 두면 far plane의 정확한 1.0도 strict less 비교를 통과할 수 있다. clip 뒤 정상 깊이는 0..1이다.
- <strong>depth test</strong>는 candidate &lt; stored일 때 통과한다. 같은 깊이 tie는 먼저 그린 샘플을 유지한다. top-left 규칙으로 같은 평면 공유 변의 경쟁을 줄인다.
- <strong>z_ndc 보간</strong>은 화면 공간에서 affine하게 보간할 수 있다. 일반 정점 속성의 perspective 보정과 구분한다.
- <strong>early depth</strong>: 비싼 texture/lighting 전에 깊이 비교를 하면 뒤에 가린 픽셀의 셰이딩을 생략할 수 있다.

## 핵심 식과 불변조건

```text
z = λ0*z0_ndc + λ1*z1_ndc + λ2*z2_ndc
pass iff finite(z) and 0 <= z <= 1 and z < depth[pixel]
on pass: depth[pixel] = z; color[pixel] = shade(fragment)
```

## 한 픽셀의 깊이 비교

λ=(3/4,1/8,1/8), 정점의 NDC 깊이=(0.2,0.6,0.8)이라 하자. 이것들은 이미 clip z/w를 계산한 값이다.

```text
candidate=(3/4)*0.2+(1/8)*0.6+(1/8)*0.8
         =0.15+0.075+0.10=0.325

stored=+infinity → 통과
stored=0.5       → 통과
stored=0.3       → 실패
stored=0.325     → 실패 (strict <)
```

깊이는 색과 같은 `pixel_index=y*width+x`에 저장한다. 먼저 비교하되 정상 fragment의 최종 색을 만들기 전까지 저장값을 덮지 않는다. 실패한 색 계산이 보이지 않는 벽처럼 다음 표면을 가려서는 안 된다. NDC 깊이가 affine인 이유는 14장에서 일반 속성과 나란히 유도한다.

## 알고리즘과 구현 순서

1. Renderer resize에서 color와 같은 픽셀 수의 f32 depth Vec을 만들고 프레임마다 infinity로 채운다.
1. perspective divide 뒤 각 screen vertex에 z_ndc를 저장한다.
1. coverage와 barycentric을 통과한 픽셀에서 z_ndc를 affine 보간한다.
1. z가 유한하고 작은 범위 epsilon 안에서 0..1인지 확인한다. 큰 이탈은 pipeline 오류 통계로 남기고 버린다.
1. candidate가 저장 깊이보다 작을 때만 깊이를 갱신하고 색을 쓴다. depth debug에서는 infinity를 배경색, 0..1을 grayscale로 표시한다.

```text
z = l0*s0.z_ndc + l1*s1.z_ndc + l2*s2.z_ndc
if not finite(z) or z < -DEPTH_EPS or z > 1+DEPTH_EPS:
  stats.invalid_depth += 1
  reject_fragment

z = clamp(z, 0, 1)
i = y * width + x
if not z < depth[i]:
  stats.depth_fail += 1
  reject_fragment

candidate_color = shade(fragment)
if not valid(candidate_color):
  stats.invalid_values += 1
  reject_fragment

depth[i], color[i] = z, candidate_color
stats.depth_pass += 1
```

## JS-Wasm 경계

깊이 버퍼는 Wasm 내부 진단 데이터다. 기본 경로에서 JS로 전체 f32 배열을 복사하지 않는다. debug view를 선택하면 Rust가 깊이를 RGBA 색 버퍼로 변환해 평소와 같은 표시 경로를 사용한다.

현재 구현의 `RenderTarget`은 같은 픽셀 인덱스를 공유하는 RGBA8와 `f32` 깊이 배열을 함께 소유한다. 색 clear 경로가 깊이도 `+infinity`로 초기화하며, 비변경 `test_depth`는 `DEPTH_RANGE_EPSILON=1e-6` 안의 작은 수치 이탈만 `0..1`로 clamp한다. 그보다 큰 범위 이탈, NaN/Inf와 타깃 밖 좌표는 `Invalid`, 저장값보다 작으면 `Passed`, 나머지는 `Failed`로 구분한다. 래스터 경로는 coverage에서 얻은 같은 barycentric으로 `z_ndc`를 screen-space affine 보간하고 깊이를 먼저 판정한다. pass 후보도 `FragmentInput`과 최종 색이 유효한지 확인한 뒤에만 색과 깊이를 함께 commit하므로, 잘못된 색 fragment가 보이지 않는 occluder로 남지 않는다. UV, world position, normal의 `1/w` 보정은 14장 범위로 남긴다.

`FrameStats`는 `depth_passed_samples`, `depth_failed_samples`, `invalid_depth_samples`를 작은 snapshot으로만 공개한다. near 빨강 `z=0.25`와 far 파랑 `z=0.75` 삼각형을 겹친 identity M/V/P fixture는 near-first와 far-first index 순서를 모두 제공한다. 두 순서의 최종 RGBA와 깊이 배열은 exact match하지만 early depth 효과 때문에 pass/fail 수는 다르다. grayscale은 `round(z*255)`를 RGB에 쓰고, range heatmap은 near를 파랑, 중간을 초록, far를 빨강으로 잇는다. 두 debug mode의 빈 픽셀은 고정 `[12,18,28,255]`이며 geometry와 깊이 통계는 표시 mode와 무관하다. wireframe/grid와 선택 정점 표시는 의도적으로 culling/depth와 무관한 X-ray overlay다.

## 코딩 에이전트 작업 명세

- Framebuffer 또는 RenderTarget에 color/depth를 함께 소유시키고 resize/clear의 길이 불변조건을 테스트한다.
- depth test를 fragment shading보다 먼저 배치하고 pass/fail 카운터를 추가한다.
- 동일한 scene의 triangle 제출 순서를 뒤집어 color buffer hash가 같은 테스트를 만든다.
- depth grayscale과 depth range heatmap debug view를 추가한다.

## 검증 기준

- 가까운 삼각형을 먼저/나중에 그린 두 결과의 RGBA가 완전히 같아야 한다.
- 가까운 삼각형을 먼저/나중에 그린 두 결과의 최종 depth 배열도 완전히 같아야 한다. pass/fail 수는 early depth 때문에 달라도 된다.
- 깊이 clear 후 모든 값이 infinity이고, 첫 정상 fragment가 통과해야 한다.
- near에 가까울수록 dark, far에 가까울수록 light 같은 명시한 grayscale 규칙이 맞아야 한다.
- NaN depth는 비교가 false라서 조용히 사라지는 데 그치지 않고 invalid_depth 통계를 올려야 한다.
- double-sided 큐브에서는 뒤 표면 fragment가 색을 덮지 못하고, back-face culling 결과는 깊이 도입 전과 같은 가시 표면을 유지해야 한다.

### 자주 생기는 오류

- clear=1.0과 strict less를 쓰면 정확히 far depth인 fragment가 통과하지 않는다. infinity 또는 일관된 less-equal 정책을 선택한다.
- view-space z와 NDC z를 섞으면 비교 방향과 범위가 달라진다. ScreenVertex 필드명을 z_ndc로 둔다.
- 색을 먼저 쓰고 depth가 실패하면 이전 색을 복원해야 하는 낭비가 생긴다. depth test를 먼저 한다.
