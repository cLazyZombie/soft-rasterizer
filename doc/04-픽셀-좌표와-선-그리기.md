# 4장. 픽셀 좌표와 선 그리기

> _선은 최종 렌더링의 주인공이 아니지만, wireframe, bounding box, 법선 방향을 보여 주는 가장 중요한 디버그 도구다._

> **이번 장의 눈에 보이는 결과**  Canvas 위에 격자, 임의 기울기의 선, 삼각형 wireframe이 끊김 없이 보이고 화면 밖으로 나간 선도 안전하게 처리된다.

## 왜 필요한가

3D 파이프라인에서 색칠된 삼각형이 보이지 않을 때 정점의 화면 좌표를 선으로 연결하면 변환 문제인지 래스터 문제인지 분리할 수 있다. 선 알고리즘은 좌표가 실수에서 정수 샘플로 바뀌는 첫 경험이기도 하다.

DDA는 식이 단순해 이해하기 좋고, Bresenham은 정수 누적 오차로 같은 일을 수행해 증분 알고리즘의 감각을 준다. 11장의 edge 함수도 매 픽셀마다 식을 새로 계산하지 않고 차이를 누적한다는 점에서 같은 생각을 사용한다.

## 배경지식

- <strong>화면 좌표</strong>는 왼쪽 위가 (0, 0), x는 오른쪽, y는 아래로 증가한다고 고정한다.
- <strong>픽셀의 셀과 샘플</strong>을 구분한다. 픽셀 (x, y)의 영역은 대략 [x, x+1) x [y, y+1)이고 대표 샘플은 (x+0.5, y+0.5)다.
- <strong>DDA</strong>는 긴 축의 길이만큼 t를 증가시키고 x, y를 선형 보간한 뒤 가장 가까운 픽셀을 선택한다.
- <strong>Bresenham</strong>은 실제 선과 선택한 픽셀 중심 사이의 오차를 정수로 누적해 다음 x 또는 y 이동을 결정한다.
- <strong>클리핑</strong>: 교육용 put_pixel이 경계를 확인하면 안전하지만 긴 화면 밖 선은 낭비가 크다. Cohen-Sutherland나 Liang-Barsky 선 클리핑은 선택 확장이다.

## 핵심 식과 불변조건

```text
DDA steps = max(abs(x1 - x0), abs(y1 - y0))
p(t) = p0 + t * (p1 - p0),  t = i / steps
선형 보간: lerp(a, b, t) = a + (b - a) * t
```

## 알고리즘과 구현 순서

1. 먼저 DDA를 구현한다. steps가 0이면 한 픽셀만 그리는 퇴화 선으로 처리한다.
1. i=0부터 steps까지 양 끝점을 모두 포함하고, x와 y를 반올림해 safe put_pixel에 전달한다.
1. 수평, 수직, 45도, 완만/급한 양/음 기울기 선을 모두 그려 octant 누락이 없는지 확인한다.
1. 선택 과제로 Bresenham all-octants 버전을 추가하고 DDA 출력과 비교한다. 디버그 모드에서는 어느 쪽을 써도 된다.
1. triangle wireframe은 세 변을 같은 색 또는 변별 색으로 그린다. 정점 점도 별도 색으로 찍어 winding을 확인하게 한다.

```text
draw_line_dda(p0, p1, color):
  dx = p1.x - p0.x
  dy = p1.y - p0.y
  steps = ceil(max(abs(dx), abs(dy)))
  if steps == 0:
    put_pixel(round(p0.x), round(p0.y), color)
    return
  for i in 0 ..= steps:
    t = i / steps
    p = p0 + t * (p1 - p0)
    put_pixel(round(p.x), round(p.y), color)
```

## JS-Wasm 경계

선 그리기는 Rust frame 안의 debug draw pass다. JS Canvas의 stroke나 lineTo를 쓰면 실제 Wasm 좌표 규약과 다른 렌더러를 보게 되므로, overlay 텍스트 외의 기하 디버그는 같은 프레임버퍼에 그린다.

## 코딩 에이전트 작업 명세

- Vec2와 Color를 최소 정의하고 DDA 선, 점, 사각형 outline, wireframe helper를 추가한다.
- safe put_pixel 경로를 사용해 화면 밖 좌표가 있어도 메모리 오류가 없게 한다.
- 모든 octant를 한 화면에 보여 주는 debug scene과 작은 예상 이미지 테스트를 만든다.
- Bresenham은 선택 구현으로 분리하고, 기본 커리큘럼의 다음 단계가 이 최적화에 막히지 않게 한다.

## 검증 기준

- 같은 시작/끝점, 수평/수직, 양/음 기울기, 화면 경계 교차, 완전히 화면 밖인 선을 검사한다.
- 선의 두 끝점이 모두 포함되고, 연결된 wireframe 모서리에 한 픽셀짜리 틈이 없는지 확대 확인한다.
- 64x64 golden image를 픽셀 단위로 비교해 브라우저 확대 방식과 무관한 결과를 얻는다.
- 선 디버그를 끄면 렌더 통계의 debug pixel 수가 0으로 돌아가는지 확인한다.

### 자주 생기는 오류

- 정수 나눗셈으로 t를 계산하면 대부분 0이 된다. 적어도 한 피연산자를 f32로 바꾼다.
- steps=0을 처리하지 않으면 0으로 나눈다.
- JS Canvas 선을 겹쳐 그리면 반 픽셀 정렬과 antialiasing 때문에 Rust 결과와 다르게 보여 디버깅을 오도한다.
